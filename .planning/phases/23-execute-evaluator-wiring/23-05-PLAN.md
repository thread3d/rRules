<objective>
Wire POST /v1/execute through the real EngineRegistry so the keystone scenario is observable over HTTP. This is where all four ROADMAP success criteria go green.

Purpose: The execute_single stub (execution.rs:312) builds a throwaway environment::Engine, hardcodes rules_fired to 0, and echoes the request input as facts_after (execution.rs:327). This plan rewrites it to construct a per-request engine from the shared registry, load the live ruleset, run the real evaluator (Plan 03) inside spawn_blocking, and serialize facts_after from post-execution working memory. It also builds the shared read-only ruleset snapshot (D-03), resolves/validates the engine param (L-07), and reads the two config env vars.

Output: A live POST /v1/execute that fires real rules, returns truthful rules_fired/rules_not_fired/facts_after, validates the engine param, defaults to rete when omitted, and auto-populates coverage. The Phase 23 keystone is honest end-to-end.
</objective>
