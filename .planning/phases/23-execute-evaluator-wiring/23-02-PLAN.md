<objective>
Build the rule-model extensions that make the keystone scenario representable: a full `Expression` type (D-06) so `score := score + 10` is a real action, and full `ComparisonOp` coverage in `Condition::evaluate` (D-05) so conditions match honestly across all value types.

Purpose: The milestone research under-stated two gaps. `Condition::evaluate` today only handles `Eq` on Integer/Float/String — every other op and all `Pattern` conditions fall to `_ => false` / unconditional `true` (rules.rs:176-179). And the engine has no `Expression` type at all — `Action::UpdateFact` only accepts literal `Value`s, so `score := score + 10` is not representable and ROADMAP success criterion #1 cannot pass. This plan is build, not wiring. It is independent of the engine compile-unblock (Plan 01) because `rules.rs` already compiles.

Output: An `Expression` AST modeled on the existing `Condition` AST shape, an `Action::UpdateFact` that accepts computed expressions, and a `Condition::evaluate` that implements the full operator and type matrix plus real `Pattern` matching.
</objective>
