  <name>Task 1: Expand TCK discovery + structural compare utility module</name>
  <files>engine/src/dmn/test_util.rs, engine/src/dmn/mod.rs</files>
  <action>Create `engine/src/dmn/test_util.rs` with two public functions:

**Function 1: `discover_tck_vectors(tck_root: &Path) -> Vec<TckVector>`**
- Walks the TCK fixture directory recursively (default: `tests/fixtures/tck/`)
- For each subdirectory, finds the `.dmn` model file and `-test-*.xml` test case file(s)
- Returns a struct with: dir_name, dmn_path (absolute), test_xml_path (absolute), category (derived from parent dir name)
- Skips directories that don't contain both a .dmn and a -test-*.xml file
- Uses `std::fs::read_dir` + recursion — no new dependencies

**Function 2: `structurally_equal(xml_a: &str, xml_b: &str) -> bool`**
- Normalizes two XML strings for structural comparison:
  1. Strip all whitespace between tags (collapse runs of whitespace to nothing between elements)
  2. Normalize attribute order: parse each element's attributes into a sorted map, re-emit in sorted key order
  3. Normalize namespace prefixes: map `dmndi:` / `dc:` / `di:` prefixes to their URIs and compare by URI (not prefix name). For non-DMNDI namespaces, normalize by local-name comparison.
  4. Strip XML declaration (`<?xml ...?>`) if present
  5. Normalize self-closing tags vs open/close pairs (both are valid XML)
- Returns true if the normalized forms are byte-equal
- Uses `quick_xml` NsReader for parsing (already a dependency)

**Type: TckVector { dir_name, dmn_path, test_xml_path, category }**

Also create `engine/src/dmn/test_util.rs` module and export it from `engine/src/dmn/mod.rs` as `pub mod test_util;`.

Use existing patterns from `engine/tests/feel_tck_numeric.rs` for the TCK directory walking convention (same `tests/fixtures/tck/` root path).</action>

<task type="auto">
  <name>Task 2: Scaffold TCK test runner (tck_sweep.rs)</name>
  <files>engine/tests/tck_sweep.rs, engine/tests/fixtures/tck/README.md</files>
  <action>Create `engine/tests/tck_sweep.rs` — a comprehensive TCK test runner that:

**Structure:**
- Uses `discover_tck_vectors()` from the test_util module to find all vectors
- For each vector: runs it through parser, exporter, and/or evaluator depending on what's available
- Groups results by directory/category for the summary report
- Reports: total_vectors, passed, failed, skipped, with per-directory breakdown

**Test categories (dispatch based on directory name):**
1. `0002-input-data-number/` — parse DMO + evaluate numeric input values against expected (like feel_tck_numeric.rs pattern)
2. `0100-arithmetic/`, `0103-feel-is-function/`, `0099-arithmetic-negation/` — FEEL arithmetic evaluation vectors
3. `0002-string-functions/`, `1103-feel-substring-function/`, `1104-feel-string-length-function/`, etc. — string built-in function vectors
4. `0007-date-time/`, `1115-feel-date-function/`, `1116-feel-time-function/` — temporal domain vectors
5. `0008-listGen/`, `0009-append-flatten/`, `0012-list-functions/`, etc. — list function vectors
6. `0016-some-every/`, `0033-for-loops/` — quantified expression vectors
7. `0085-decision-services/` — DRD chaining vectors (requires evaluator)
8. All directories with `-test-*.xml` files — parse the XML to extract expected values, evaluate against implementation

**For each vector:**
1. Read the .dmn file into IR via `parse_dmn()`
2. If a -test-*.xml exists: parse it to extract input scope + expected output (use quick_xml)
3. Run through appropriate layer (parser-only for import tests, parser+evaluator for evaluation tests)
4. Compare result against expected using `structurally_equal()` for XML outputs or direct Value comparison for FEEL expressions
5. Record pass/fail/skip with error message

**Skip handling:**
- Vectors requiring features not yet implemented (e.g., external Java functions, DMN 1.6 features) go to SKIP_LIST with documented reason
- Follow the pattern from `feel_tck_numeric.rs` SKIP_LIST — every skip must have a category and reason

**Output format on test completion:**
```
TCK Sweep Summary:
  Total vectors discovered:  XX
  Passed:                    YY
  Failed:                    ZZ
  Skipped (documented):      WW
  
By category:
  compliance-level-2/       : 5/10 passed, 3 skipped, 2 failed
  compliance-level-3/       : 8/20 passed, 5 skipped, 7 failed
  ...
```

- List all upstream directories that are discoverable (even if not all are executed)
- Document the skip categories and reasons

**File paths reference:** Use `Path::new(env!("CARGO_MANIFEST_DIR")).join("tests/fixtures/tck")` for TCK root, same pattern as feel_tck_numeric.rs.</action>

README.md updated with full sweep provenance.</done>
