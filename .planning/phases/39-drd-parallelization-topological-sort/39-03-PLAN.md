# PERF-06 — Per-Thread Cache Patterns (Phase 39, plan 03)

## What shipped

A `thread_local!` L1 FEEL-AST cache in `engine/src/dmn/feel/cache.rs`, sitting
in front of the shared `DashMap<String, Arc<FeelExpression>>`.

### Design

- **Key:** the existing canonical `cell_key(src, entry)` = `(entry-point kind,
  trimmed content)`. FEEL text→AST is a pure function of this pair, so the L1
  is correct across model reloads and across `FeelAstCache` instances on the
  same thread — a cell parsed for model A is bit-identical to the same cell in
  model B.
- **Values:** `Weak<FeelExpression>`. The shared `DashMap` (or a caller's held
  `Arc`) is the sole authority keeping an AST alive. The L1 never keeps an AST
  alive past its real owners → no per-thread memory leak on long-lived worker
  threads (rayon pool from PERF-09, tokio workers). A dead Weak (authority
  evicted/dropped the strong) fails to `upgrade` and is purged lazily; the call
  falls through to the shared map and re-parses. No stale Arc is ever returned.
- **Hot path:** L1 hit → return the SAME `Arc` the shared map owns, **no
  shard-lock acquisition** — the dominant cost under high concurrency.
- **Bound:** FIFO, 1024 entries/thread.

### Latent bug fixed

`engine/Cargo.toml` had `harness = true` for `dmn_benchmarks`. With
`criterion_main!` providing `main`, libtest's harness shadowed it and `make
bench` silently measured nothing. Corrected to `harness = false`. This
unblocks PERF-06's benchmark and PERF-03's baseline comparison.

## Benchmark (PERF-06 requirement)

`bench_feel_cache_concurrency` — ThreadLocal vs DashMap at 16 and 32 threads.
Each sample spawns N threads × 500 `get_or_parse` calls on one shared
`FeelAstCache`.

| Variant | 16 threads | 32 threads |
|---------|-----------:|-----------:|
| `thread_local` (L1 hot, lock-free) | 3.87 ms | 7.59 ms |
| `dashmap_contended` (L1 thrash → shard locks) | 43.18 ms | 122.56 ms |
| **ThreadLocal speedup** | **11.1×** | **16.1×** |

Target was 4–20× throughput improvement at high concurrency — **met** (11× @16t,
16× @32t). Contention scales superlinearly in the DashMap regime (43→123 ms
going 16→32 threads) while the ThreadLocal regime scales near-linearly
(3.9→7.6 ms) because the hot path is lock-free.
