<objective>
Implement all 10 FEEL boxed-expression evaluators with recursive dispatch, and the boxed-context topological (dependency-order) evaluation with DFS color-marking cycle detection — the DMN-15 surface.

Purpose: DMN-15 — boxed expressions are FEEL's structured-literal forms. The critical correctness property is boxed-context topological evaluation: entries must evaluate in dependency order (an entry referencing another entry must evaluate after it), and cycles must be detected (not infinite-loop). The user's locked flat-Scope + explicit dependency tracking is the mechanism.

  <action>
    Implement `eval_context_topo(entries: &[(String, FeelExpression)], scope: &Scope) -> Result<HashMap<String, Value>, ContextCycleError>` per research Pattern 3 and the "Boxed-context topological evaluation" 6-step procedure:

    1. For each `(key, expr)`, compute the free variables (names referenced in `expr` but not bound in the outer scope). A `free_vars(&FeelExpression) -> Vec<String>` helper walks the AST collecting `Name`/`QualifiedName` identifiers. Reuse this helper for the `deps` map.
    2. Build the dependency graph: edge `key -> dep` for each free var that is also a key in `entries`. (Only intra-context dependencies matter for topo order.)
    3. DFS color-marking cycle detection: `Color { White, Gray, Black }`. A Gray->Gray edge is a cycle. On cycle detection, the cyclic entries evaluate to `Value::Null` and a `ContextCycleError` (carrying source location — the Span of the cyclic entry's expression) is recorded/returned.
    4. DFS post-order gives the topological order (reverse of finishing times).
    5. Evaluate entries in topological order, binding each result into a working `Scope` (a child flat Scope copy with the outer scope's bindings + each evaluated entry). Record `deps` for each entry (the intra-context dependency names). A cyclic entry -> `Value::Null`.
    6. Return the resolved `HashMap<String, Value>` as `Value::Object`.

    Define `ContextCycleError { cyclic_entries: Vec<String>, spans: Vec<Span> }` (or a recorded eval error type consistent with the 31-02 eval-error-carrying-source-location decision). The `Context` arm maps the Result: Ok -> Value::Object; Err -> Value::Object where cyclic entries are Null AND the error is recorded (per CONTEXT.md eval-error propagation — the error is recorded for the Phase 33 inference trace, not returned as a panic).

    Add inline tests for the 2-cycle, 3-cycle, self-reference, and out-of-order DAG cases. Add a proptest with a committed seed for the DAG-order-invariance property.
  </action>
