**DecisionTableEvaluator struct:**
```rust
pub struct DecisionTableEvaluator;
impl DecisionTableEvaluator {
    pub fn evaluate(
        table: &model::DecisionTable,
        scope: &feel::eval::Scope,
        cache: &feel::cache::FeelAstCache,
    ) -> Result<value::Value, DecisionTableError>
}
```

**Core evaluation flow inside `evaluate()`:**
1. For each rule in `table.rules`, evaluate ALL input clauses against the scope using pre-parsed ASTs from cache — collect matching rules as `(rule_index, output_values: Vec<Value>)` pairs
2. Dispatch to hit-policy-specific evaluator based on `table.hit_policy`
3. Return aggregated result

**input_clause_matches helper (private):**
```rust
fn input_clause_matches(
    clause: &model::InputClause,
    rule_entry: &model::RuleEntry,
    scope: &feel::eval::Scope,
    cache: &feel::cache::FeelAstCache,
) -> Option<bool> {
    // 1. Parse the RuleEntry.text as a SimpleUnaryTests AST via cache
    let ast = cache.get_or_parse(&rule_entry.text.content, feel::cache::ParseEntry::SimpleUnaryTests);
    // 2. Evaluate the input expression (e.g., "applicant.age") against scope to get the input value
    let input_expr_ast = cache.get_or_parse(&clause.input_expression, feel::cache::ParseEntry::Expression);
    let input_value = evaluate(&input_expr_ast, scope);
    // 3. Use eval_in_unary_test(input_value, &ast) — returns Option<bool> (None=null propagation)
    // 4. None -> treat as non-match (three-valued: unknown is not true)
}
```

- Dispatch to policy-specific handler based on `table.hit_policy` variant
- Each policy handler signature: `fn handle_<policy>(matches: &[(usize, Vec<Value>)], table: &DecisionTable) -> Result<Value, DecisionTableError>`

Complete the three foundational hit policies in `engine/src/dmn/decision_table.rs`.

**UNIQUE hit policy (DMN Clause 8.2.12):**
- If zero rules match: return null for each output column (use output clause's defaultOutputEntry if present, else Value::Null)
- If exactly one rule matches: return that rule's outputs as a boxed context Value (context with output-clause names as keys mapped to their values) — actually for simplicity and spec compliance, return the first single output value directly when there is one output column; for multi-output UNIQUE tables, wrap in a context
- If multiple rules match: return `DecisionTableError::HitPolicyViolation { policy: "UNIQUE".into(), message: format!("{} rules matched but UNIQUE allows exactly one", count) }`

**ANY hit policy (DMN Clause 8.2.12):**
- If zero rules match: same as UNIQUE — null per output column with defaults
- If one or more rules match: collect all outputs, verify they agree on every output column's value; if any disagreement → `DecisionTableError::HitPolicyViolation { policy: "ANY".into(), message: format!("conflicting outputs for column '{}': {:?} vs {:?}", col_name, val_a, val_b) }`; if all agree, return the agreed-upon values (same shape as single-match case)
- ANY does NOT collect — it validates consistency

**FIRST hit policy (DMN Clause 8.2.12):**
- If zero rules match: same null-with-defaults behavior
- Always returns the first matching rule's outputs by document order (index 0 of matches slice); no conflict detection needed

**Output shape convention:** For single-output tables, return the Value directly. For multi-output tables, return a boxed context (`Value::Object`) with output-clause names as keys. Use `clause.label.or(clause.name).unwrap_or_else(|| format!("output_{}", idx))` for the key name to ensure every column has an identifier.

**Hit-policy dispatch wiring:** Update the `evaluate()` dispatch from the stub UNIQUE implementation to a proper match on `table.hit_policy`:
```rust
match table.hit_policy {

    _ => Err(DecisionTableError::Other("hit policy not yet implemented".into())),
}
```
