## Objective

Optimize the FEEL parser and evaluator hot-paths based on Phase 36 baselines. This phase implements optimization work identified during measurement: AST cache warming, lexer caching, evaluation hot-path improvements, and DRD parallelization.

## Scope

- **In scope:** Parser optimizations (lexer caching, incremental parsing), evaluator optimizations (AST cache pre-warming, memoization, Scope lookup), DRD topological sort + parallelization
- **Out of scope:** Algorithm redesign; any functional changes to FEEL semantics; new built-in functions

## Requirements

| ID | Description | Gate |
|----|-------------|------|
| OPT-01 | Parser throughput improves ≥20% vs Phase 36 baseline on representative corpus | PASS |
| OPT-02 | FEEL evaluator latency improves ≥15% vs Phase 36 baseline for typical expressions | PASS |
| OPT-03 | AST cache pre-warming at model load time eliminates per-eval parse overhead | PASS |
| OPT-04 | DRD resolution parallelizes independent decisions (same DAG level) | PASS |

## Success Criteria

1. `cargo bench --bench dmn_benchmarks` shows ≥20% improvement in parser throughput vs Phase 36 baseline
2. FEEL evaluator benchmarks show ≥15% latency improvement for expressions of varying complexity
3. AST cache warming is wired into DMN IR loader (no parse-on-eval overhead)
4. DRD resolution benchmarks show parallel speedup for multi-output decision services with independent decisions

## Key Decisions

- **AST cache pre-warming:** Parse all cell FEEL during import, not during evaluation — closes the "parse every eval" performance bug
- **Lexer token cache:** `DashMap<String, Vec<Token>>` for repeated expression prefixes (e.g., user typing in editor)
- **DRD parallelization:** Use tokio's `spawn` for independent DAG nodes; join at decision service boundary
- **Scope optimization:** `FastHashMap` from hashbrown crate for common path lookups

## Dependencies

- Phase 36 (baselines) — must have measurements before optimization targets can be set
