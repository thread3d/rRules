`pub fn parse_at_literal(s: &str) -> Option<Value>` — dispatch by prefix per research Code Examples FEEL @\"\" literal parsing block: if s starts with 'P' or '-P' call parse_duration (years-months if the body has no 'T'/'H'/'M'<'S' day-time markers, else day-time); if s contains ':' and no '-' before the time part call parse_time returning Value::Time; if s contains '-' and 'T' call parse_date_time returning Value::DateTimeTz; if s contains '-' and no 'T' parse as NaiveDate via NaiveDate::parse_from_str(s, "%Y-%m-%d") returning Value::Date. parse_date_time must detect the '@Zone/Name' suffix (split at '@' after the time part) and resolve the IANA zone via the chrono_tz::Tz::from_str or the chrono_tz macro (e.g. chrono_tz::Australia::Melbourne) — return DateTimeValue::Iana(DateTime<chrono_tz::Tz>) when the suffix is present, DateTimeValue::Fixed(DateTime<FixedOffset>) when an offset (+11:00) is present, DateTimeValue::Local(NaiveDateTime) when neither. parse_duration parses the XDM dayTimeDuration / yearMonthDuration lexical form (P[n]Y[n]M for years-months, P[n]DT[n]H[n]M[n]S for days-time) into YearsMonthsDuration{months} (total months, normalized so months is the sum of years*12 + months) or TimeDelta (for days-time). `pub fn format_value(v: &Value) -> Option<String>` — the inverse of parse_at_literal: for Value::Date emit "YYYY-MM-DD"; for Value::Time emit "HH:mm:ss" (with offset suffix if Offset variant); for Value::DateTimeTz emit "YYYY-MM-DDTHH:mm:ss" followed by "@Zone/Name" for the Iana variant (Pitfall 3 — re-emit the IANA zone name, NOT the fixed offset) or "+HH:mm" for the Fixed variant; for Value::DaysTimeDuration emit the XDM dayTimeDuration form; for Value::YearsMonthsDuration emit "P[n]Y[n]M".
