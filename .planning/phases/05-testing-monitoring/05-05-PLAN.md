  <name>Task 01: Define KPI models and aggregation logic</name>
  <files>src/monitoring/dashboard/mod.rs, src/monitoring/dashboard/kpis.rs</files>
  <action>Create the dashboard KPI framework:

1. `src/monitoring/dashboard/mod.rs` - Module structure:
   ```rust
   pub mod api;
   pub mod kpis;
   pub use kpis::{TechnicalKpi, BusinessKpi, DashboardData};
   ```

2. `src/monitoring/dashboard/kpis.rs` - KPI definitions:

   **Technical KPIs:**
   - Throughput (RPS): requests per second over time window
   - Latency P50/P95/P99: percentile latencies from histogram
   - Error rate: % of executions with errors
   - Active rules: count of rules that fired in window

   **Business KPIs:**
   - Rules executed per hour: total rule firings
   - Decisions made: unique decision contexts
   - Approval times: time from submission to approval
   - Customer segments affected: by tag or customer type

3. Aggregation methods:
   - `get_technical_kpis(window: Window) -> Vec<TechnicalKpi>`
   - `get_business_kpis(window: Window) -> Vec<BusinessKpi>`
   - `get_dashboard_data() -> DashboardData` (combined view)

All KPIs should be time-window configurable (5m, 15m, 1h, 24h).</action>
  <verify> cargo check succeeds with all KPI types defined </verify>
  <done>KPI models and aggregation logic implemented</done>
</task>

<task type="auto">
  <name>Task 02: Implement REST API endpoints for dashboard data</name>
  <files>src/monitoring/dashboard/api.rs</files>
  <action>Create the dashboard API endpoints in `src/monitoring/dashboard/api.rs`:

1. Endpoints (REST /v1/dashboard/*):
   - `GET /v1/dashboard/technical?window=5m` - Technical KPIs
   - `GET /v1/dashboard/business?window=5m` - Business KPIs
   - `GET /v1/dashboard/all?window=5m` - Combined view

2. Response format:
   ```json
   {
     "timestamp": "2026-05-24T10:30:00Z",
     "window": "5m",
     "kpi": "throughput_rps",
     "value": 125.7,
     "trend": "up" | "down" | "stable"
   }
   ```

3. Access control:
   - RBAC integration: admin can see all KPIs
   - Reviewer role: read-only access to technical metrics
   - Author role: business metrics only

4. Error handling:
   - Invalid window parameter (must be 5m, 15m, 1h, 24h)
   - Unauthorized access with 403 response
   - Empty data periods with appropriate message

The API should be fast and cacheable for frequent dashboard refreshes.</action>
  <verify> API endpoints return correct KPI values for technical and business categories </verify>
  <done>Dashboard API provides REST endpoints for all technical + business KPIs</done>
</task>
