# Phase 05 Plan 06: Dead Rule Detection

## Objective

Implement dead rule detection algorithm to identify rules that never fire despite being active.

**Purpose:** Prevent technical debt accumulation by finding unused rules. Dead rules indicate either obsolete business logic or configuration issues, and should be reviewed for removal or activation.

**Output:** Complete dead rule detection system with alerting and reporting.

<task type="auto">
  <name>Task 02: Implement dead rule detection algorithm</name>
  <files>src/monitoring/detection/dead_rules.rs</files>
  <action>Implement the dead rule detection logic:

1. Detection process:
   - Query all active rules from rule storage
   - For each rule, check metrics collector for last execution time
   - Compare against `dead_threshold_hours` config

2. Scoring and categorization:
   - **Definitely dead**: Never fired, included in no recent executions
   - **Possibly dead**: Fired before threshold but not recently
   - **Active**: Fired within threshold period

3. Context analysis:
   - Which rule sets include this rule?
   - How many times was it included vs executed?
   - Any conditional rules that may never match?

4. Reporting:
   - List of dead rules with metadata
   - Suggested action (review, archive, remove)
   - Ownership information for notification

Integration: Use metrics collector's histogram data to find last execution time.</action>
  <verify> Detection correctly identifies rules based on last firing time vs threshold </verify>
  <done>Dead rule detection algorithm correctly identifies inactive rules</done>
</task>
