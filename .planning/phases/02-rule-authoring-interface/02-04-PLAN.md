## Phase 02-04: Rule Templates with Parameterization

### Objective
Build the rule template system with class-based inheritance for parameterization, supporting user-private and shared storage models, and full version history with rollback capability.

**Purpose:** Template reuse is essential for enterprise-scale rule management. The class-based inheritance model allows creating base templates that child rules extend with specific values - enabling consistent rule patterns while allowing customization.

**Output:**
- `template-system.ts`: Parameterization engine with inheritance merge logic
- `storage.ts`: Hybrid storage layer with access control
- `version-history.tsx`: Version tracking and rollback UI
- `template-manager.tsx`: Complete template management interface

### Context

**Locked Decisions from 02-CONTEXT.md:**
- **RT-P1**: Class-based inheritance for parameterization - templates define base structure; instances extend with specific values
- **RT-S1**: User-private + shared storage model - users have private templates plus access to team-shared ones
- **RT-V1**: Full version history - track changes to templates with rollback capability

### Implementation Details

**Template Structure:**
```typescript
interface Template {
  id: string;
  name: string;
  description: string;
  parameters: Parameter[];
  baseStructure: RuleTemplateAST; // AST of the rule template
}
```

**Parameter Substitution:**
- `{parameter_name}` syntax in templates replaced with user values
- Default values supported for optional parameters
- Validation ensures all required parameters have values

**Storage Model:**
- User-private: templates created by user (full access)
- Shared-team: templates marked visible to team (read-only, can duplicate)
- System: built-in templates (read-only)

Build the template parameterization and inheritance system:

1. Define template structure types:
   - Template: { id, name, description, parameters: Parameter[], baseStructure }
   - Parameter: { name, type: string|number|boolean, defaultValue?: string }
   - RuleTemplateAST: abstract syntax tree representation

2. Implement instantiateTemplate(template, values):
   - Clone template baseStructure (deep copy)
   - Replace all {parameter_name} placeholders with user-provided values
   - Validate all required parameters have values
   - Return instantiated rule AST

3. Create extends functionality for inheritance:
   - Parse template references in rule definitions (`extends "template_id"`)
   - Merge parent template AST with child overrides recursively
   - Support multiple levels: grandparent -> parent -> child

4. Build parameter resolution logic:
   - Detect {param_name} syntax using regex
   - Replace with user-provided values or defaultValue if available
   - Track unresolved parameters as errors for UI feedback

5. Add tests for parameter substitution and inheritance merge with edge cases
