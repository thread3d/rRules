## Phase 02-01: Web-Based IDE with Syntax Highlighting

### Objective
Build the core web-based IDE component using CodeMirror 6 as the editor architecture, providing syntax highlighting for the rule DSL and real-time validation feedback.

**Purpose:** Rule authoring starts with a professional-grade editing experience. CodeMirror 6 is lightweight, extensible, and React-friendly—ideal for integrating DSL-specific features like custom token types and linting.

**Output:**
- `code-mirror-editor.tsx`: React component wrapping CodeMirror 6 with rule-specific configuration
- `syntax-highlighter.ts`: DSL grammar definitions for the rule language
- `realtime-validator.ts`: Syntax validation using CodeMirror's lint extension
- `dual-pane-view.tsx`: Layout component enabling side-by-side editor and guided builder

### Context

**Phase Goal (from ROADMAP.md):**
Provide intuitive web-based tools for business users and developers to create, edit, and validate rules.

**Locked Decisions from 02-CONTEXT.md:**
- **IDE-A1**: Use CodeMirror 6 as editor architecture
- **IDE-A2**: Hybrid validation approach - syntax real-time, semantic on save
- **IDE-A3**: Dual-pane mode workflow with both views visible side-by-side

### Implementation Details

**CodeMirror 6 Configuration:**
- Initialize editor with custom DSL language support via `LRLanguage` and `LanguageSupport`
- Configure line numbers, auto-close brackets, basic autocompletion for keywords
- Support code folding for rule blocks (condition/action sections)
- Theme: Light theme with custom token colors for DSL elements

**Syntax Highlighter Implementation:**
Define token types for:
- `keyword`: IF, THEN, ELSE, WHEN, AND, OR, NOT
- `function`: Action names like `add_tag`, `apply_discount`
- `variable`: Placeholder syntax `{customer_field}`, `{threshold_value}`
- `literal`: String/number literals
- `operator`: Comparison operators (>, <, ==, !=)
- `comment`: DSL comment syntax

**Real-time Syntax Validation:**
- Use CodeMirror's `lint` extension with `lintProvider`
- Define a linter that scans document for:
  - Missing required clauses (IF without THEN)
  - Unmatched braces in `{placeholder}` syntax
  - Invalid operator usage
  - Unknown keywords or functions
- Display diagnostics inline at error locations

**Dual-Pane View:**
- CSS Grid layout with responsive columns (50/50 split on desktop, stackable on mobile)
- Toggle to show/hide each pane independently
- Shared toolbar for common actions (save, validate, clear)
- Sync scroll positions when relevant
