# Version Control Decisions (D-05 from CONTEXT.md)

## Branch Strategy:
| Branch | Purpose | Protection |
|--------|---------|------------|
| main | Production-ready rules | Protected - no direct pushes |
| develop | Staging with latest features | Protected - requires PR review |
| feature/* | Temporary rule development | Unprotected, auto-cleanup |

## Merge Process (per D-05):
1. Feature branch: `git checkout -b feature/new-risk-scoring`
2. Develop and test rules in feature branch
3. Create pull request to develop
4. All approvals must be complete for affected rules
5. Squash merge to develop
6. When ready, merge develop to main

## Git Storage Integration (per PROJECT.md):
- Hybrid Git + PostgreSQL: Git for versioning rules as code, DB for metadata
- Rules stored as YAML/JSON files in `rules/` directory
- Git commits track rule versions with automatic timestamps

  <action>Create the merging logic:
  
1. `src/governance/versioning/merging.rs` with:
   
   - `validate_merge_requirements(source_branch: &str, target_branch: &str) -> Result<MergeReady, MergeError>`
     - Validates all rules modified in source branch have:
       * No pending approvals (if target is main or develop)
       * All required reviewers approved
     - Returns MergeReady with list of affected rules if successful
   
   - `merge_to_target(source: &str, target: &str, user_id: &str) -> Result<MergeResult, MergeError>`
     - Creates merge commit on target branch
     - Squash merge for develop/main (single commit)
     - Fast-forward allowed for feature merges
     - Returns merge result with commit SHA and affected rules
   
   - `get_conflicting_rules(source_branch: &str, target_branch: &str) -> Vec<RuleConflict>`
     - Identifies rules with conflicting modifications between branches

2. Merge workflow:
   ```rust
   // 1. Validate source branch exists and is not protected
   validate_branch_name(source)?;
   
   // 2. Get all rules modified in source branch (via git diff)
   let modified_rules = get_modified_rules(source, target);
   
   // 3. For each rule, verify no pending approvals
   for rule_id in &modified_rules {
       let pending = approval::get_pending_approvals(rule_id)?;
       if !pending.is_empty() {
           return Err(MergeError::PendingApprovals { rule_id });
       }
   }
   
   // 4. Perform the merge (git2 crate)
   git_repo.merge_branches(source, target)?;
   ```

3. Error handling:
   - MergeError::ProtectedBranch when attempting direct commit to protected branch
   - MergeError::PendingApprovals when approvals incomplete
   - MergeError::Conflict when git detects file conflicts</action>
