# Approval Workflow Decisions (D-04 from CONTEXT.md)

## Multi-tier Approval Hierarchy:
| Rule Risk Level | Reviewers Required |
|-----------------|-------------------|
| Low-risk | Single reviewer approval |
| Medium-risk | Two reviewers (one must be senior author) |
| High-risk | Three reviewers with voting (majority required) |

## Criticality Determination (Claude's discretion - D-04):
Factors for risk level:
1. Rule scope: Global/system rules = high; specific use case = low
2. Business impact: Financial/ compliance = high; informational = low
3. Complexity: Complex logic = medium/high
4. Historical issues: Rules with past bugs = medium

## State Machine:
```
Draft → Submitted → [In Review] → Approved/Rejected
                        ↳ Escalated (for multi-tier)
```

# PostgreSQL Tables Required
```sql
-- Approval submissions
CREATE TABLE rule_approvals (
    id UUID PRIMARY KEY,
    rule_id TEXT NOT NULL REFERENCES rules(id),
    submitted_by TEXT NOT NULL REFERENCES users(username),
    status VARCHAR(20) NOT NULL DEFAULT 'pending',
    risk_level VARCHAR(10) NOT NULL,
    reviewers JSONB,  -- Array of {user_id, approved, comment}
    required_count INTEGER NOT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Approval notifications
CREATE TABLE approval_notifications (
    id UUID PRIMARY KEY,
    approval_id UUID REFERENCES rule_approvals(id),
    user_id TEXT NOT NULL,
    status VARCHAR(20) DEFAULT 'pending',
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```
