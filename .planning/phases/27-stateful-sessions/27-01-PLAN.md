|----------|-------------|
| client → API (POST /v1/execute with session_id) | Untrusted client supplies `session_id` (idempotency alias), `engine` param, `facts`. The sessionful path resolves the alias to a server UUID, validates engine against `registry.available_engines()`, and treats client input as data (not as a primary key). |
| client → API (DELETE /v1/execute/session/{id}, POST /v1/execute/session/{id}/reset) | Untrusted client supplies a path `{id}` (the client alias). The handler resolves it to a server UUID and 404s if not found — no information leak beyond "exists or not". |
| API → in-memory SessionManager | The registry is server-side only; `web::Data<Arc<SessionManager>>` is shared across actix workers. No cross-session data sharing (anti-feature). |
| SessionManager → background sweep task | `tokio::spawn`'d task holds an `Arc<SessionManager>` clone; runs `sweep_expired` on a `tokio::time::interval`. Process-lifetime (no CancellationToken — matches `start_file_watcher`). |
| SessionManager → prometheus Registry | The `rrules_sessions_active` IntGauge registers on the Phase-24 dedicated `Registry` (NOT `default_registry()` — Pitfall 24-A: `register()` panics on duplicate names). |
</trust Boundaries>
