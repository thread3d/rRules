<objective>
Convert `RuleExecutionTracker` (`engine/src/monitoring/detection.rs:64-191`) from a locally-instantiated `&mut self` struct into a process-wide `LazyLock<Mutex<TrackerState>>` singleton mirroring the existing `CoverageTracking` pattern (`engine/src/monitoring/coverage.rs:83-158`), and migrate its 6 in-crate tests to the singleton API with `#[serial]` + `clear()` isolation plus a new `test_once_per_rule`.

Purpose: This is the foundation of Phase 26. The dead-rules panel (`GET /v1/metrics/dead-rules`) is broken (Pitfall 3) because `dead_rules_endpoint` constructs a fresh empty `RuleExecutionTracker::new()` per request — always returning `[]`. The fix requires a process-wide singleton that the live evaluator can record into and the endpoint can read from. Without this plan, Plan 26-02's recording call sites and endpoint rewrite have nothing to record into / read from. D-01 locks the singleton shape (mirror `CoverageTracking`); D-04 locks `new()` deprecation + test migration; D-06 locks internal timestamp stamping.

Output: A working `RuleExecutionTracker` singleton with associated-function API, deprecated `new()`, owned `find_dead_rules()`, `clear()` for test isolation, and a passing rewritten unit-test suite including `test_once_per_rule`. Tests are written RED first (Wave 0), then the singleton implementation makes them GREEN.
</objective>
