**Backend fix (Pitfall 3, T-22-04):** The backend `create_branch` handler (`branches.rs:89`) hardcodes `"feature/default"` as the branch name — `CreateBranchRequest` (lines 22-29) has only `source_branch` and `from_commit`, no `name`. Every "New Branch" creates `feature/default` regardless of input; a second one fails. This plan MUST add a `name` field to `CreateBranchRequest`, pass it through to `VersionControlRepo::create_branch`, and sanitize it (T-22-04 branch-name injection). This is in-scope for D-22-11 ("calls /v1/branches CRUD" — working create is part of CRUD).

Purpose: Closes GOV-04 (version control & branching with conflict resolution) and the FRONTEND-01 side-by-side-diff portion. Split from 22-05 for context budget (interactive UI + backend fix is its own cluster).
Output: Working branch CRUD, merge-with-conflict UI, side-by-side diff, and the create_branch backend fix with a regression-guard test.
</objective>
