<objective>
Plan 22-01: API path alignment — the Wave 1 foundation for the entire phase.

Eliminate the single systematic root cause breaking every frontend axios flow: frontend baseURL `/api/v1` vs backend scope `/v1` (no `/api` anywhere). Align the frontend to `/v1` per D-22-04, make `VITE_API_URL` configurable-absolute per D-22-05, retarget the vite proxy, and add `actix-cors` so the separate-host prod mode declared in D-22-05 is real (Pitfall 2 — `actix-cors` is verified ABSENT despite STATE.md's false P2 claim). No backend route prefix change to the `/v1` scope itself. Additionally, SPLIT `configure_metrics` so the MON-03/MON-04 dashboard endpoints (`/metrics/dead-rules`, `/metrics/coverage`) move from root into the `/v1` scope (becoming `/v1/metrics/dead-rules`, `/v1/metrics/coverage`) — this unblocks the dashboard fetch wiring in 22-03. The Prometheus `/metrics` endpoint stays at root per REQUIREMENTS.md.

Purpose: This is the precondition for plans 22-02..22-06 — none of them can verify end-to-end until paths align. Done first, in isolation.
Output: A frontend that talks to `/v1` (dev via proxy, prod via `VITE_API_URL`) and a backend that sends CORS headers.
