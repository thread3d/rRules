# Phase 22 Plan 03: Router Codegen + Mount Orphaned Routes + Dashboard Wiring Summary

**Replaced the stale hand-maintained route tree with @tanstack/router-plugin file-based codegen, mounted AuthProvider + all 11 orphaned routes (rules/monitoring/governance), wired the MON-03/MON-04 dashboards to /v1/metrics/* with backend→frontend contract adapters, and closed the phase-wide P-2 (no /api/v1 anywhere in frontend/src/) — the mount precondition for 22-05/22-06.**

## Performance

- **Duration:** ~30 min
- **Tasks:** 2 implementation commits (Tasks 2+3 combined; Task 4 separate)
- **Files:** 15 created, 7 modified, 12 deleted
- **Build:** `cd frontend && npm run build` exits 0 (was failing with 32 pre-existing tsc errors)

## Accomplishments

- Installed `@tanstack/router-plugin` ^1.168.19 and upgraded `@tanstack/react-router` ^1.8.0 → ^1.170.17 + `@tanstack/router-devtools` → ^1.167.0 (Pitfall 5 version gap closed).
- Configured the codegen plugin in `vite.config.ts` BEFORE `react()` (RESEARCH § Pattern 1) so `routeTree.gen.ts` is generated before the React plugin processes imports.
- Rewrote `main.tsx` to import `routeTree` from `./routeTree.gen` (generated) and wrap `<RouterProvider>` in `<AuthProvider>` (D-22-09) so `useAuth()`/`usePermission()` stop throwing.
- Created `__root.tsx` (createRootRoute) and `index.tsx` (createFileRoute('/')) as the codegen source of truth; created `/login` route so Navbar/ProtectedRoute typed navigation resolves.
- Created all 11 orphaned route files as thin `createFileRoute('/path')({ component: ExistingFeatureComponent })` wrappers: `/rules/{index,new,$id/edit}` (the last two render RuleEditor + DecisionTable + HitPolicySelector deep-linkably per D-22-08, not modal), `/monitoring/{index,dead-rules,coverage,engine}`, `/governance/{approvals,audit,branches,rbac}`.
- Deleted the stale legacy monitoring tree (`src/monitoring/`, `features/monitoring/routes.tsx`) and stale flat routes (`_layout.gen.ts`, `_layout.tsx`, `routes/monitoring.tsx`, `routes/rules.tsx`) — these caused the 32 pre-existing tsc errors flagged by 22-01/22-04 and were only imported by other deleted stale files.
- Wired DeadRuleReportDashboard to `${VITE_API_URL||'/v1'}/metrics/dead-rules` with a `Vec<String>→DeadRuleInfo[]` adapter (backend returns rule IDs, not the frontend shape — Pitfall 4).
- Wired RuleCoverageDashboard to `${VITE_API_URL||'/v1'}/metrics/coverage` with a `{rules[],summary}→RuleCoverageData[]` adapter (per-rule coveragePercent = evaluated>0 ? fired/evaluated*100 : 0).
- **Phase-wide P-2 closed:** `grep -rn '/api/v1' frontend/src/` returns nothing (22-01 fixed client.ts + auth-context.tsx; 22-04 fixed useEngineMetrics.ts; this plan fixed the last two dashboard files).

## Task Commits

1. **Tasks 2+3: TanStack router codegen + mount orphaned routes + AuthProvider** — `f4b5c8134` (feat). Combined because routeTree.gen.ts is generated from every route file — the build only goes green with all routes present (see Decisions).
2. **Task 4: wire MON-03/MON-04 dashboards to /v1/metrics/* + contract adapters** — `6c956a142` (feat).

## Decisions Made

- **Combined Tasks 2+3 commit.** routeTree.gen.ts is generated by the plugin from EVERY file under src/routes/. The build only goes green once all routes + __root + index exist. Splitting them would require temporarily removing route files to make the Task 2 build-gate pass — artificial and fragile. The codegen setup and the routes it generates are one functional unit. Task 4 (dashboard fetch wiring) is a clean separate commit. Documented here per the deviation rule.
- **Deleted the stale legacy monitoring tree.** `src/monitoring/Dashboard.tsx`, `components/Chart.tsx` (29 of the 32 tsc errors — recharts type re-exports that no longer exist), `Panel.tsx`, `StatusIndicator.tsx`, and `features/monitoring/routes.tsx` (react-router-dom based, react-router-dom not installed) were flagged by 22-01/22-04 as owned by 22-03. Nothing in `features/` imported them; only `routes/monitoring.tsx` (also deleted) referenced them. Removing them is what made the build green. The new monitoring dashboards live in `features/monitoring/dashboards/` and are mounted via file-based routes.
- **Created /login route (not in plan's route list).** Navbar.tsx and ProtectedRoute.tsx use typed `<Link to='/login'/>` / `<Navigate to='/login'/>`. Once the router is registered with the generated route tree, the typed `to` prop validates against known routes and /login was not registered → tsc error. A minimal login page (uses auth-context `login()`) is the correct fix; it completes the auth flow mounted in 22-02 and is a small, in-scope addition for the AuthProvider mount task (D-22-09).
- **RBAC admin route is minimal.** `features/governance/rbac` only contains `ProtectedRoute` + `usePermission` helpers — no admin UI component. The `/governance/rbac` route mounts a minimal page using `useAuth()` to display the current user's role + permissions, with a TODO(22-05/22-06) for the full management UI. The plan's bar for governance routes is mounting + build-green (fetch wiring lands in 22-05/22-06).
- **Trivial BranchManager fix.** Removed the unused `fetchBranches` stub (TS6133) — BranchManager is owned by 22-06's rewrite, but the 1-line removal was necessary for the build-gate and is non-semantic. Documented with a TODO(22-06).
- **Coverage adapter per-rule coveragePercent.** Verified the backend `CoverageTracking::to_json` shape in `engine/src/monitoring/coverage.rs`: `{rules:[{rule_id, evaluated, fired, evaluation_count, fire_count, skipped_reason}], summary:{total_rules, evaluated_count, fired_count, coverage_percent}}`. Per-rule coveragePercent = `evaluation_count>0 ? (fire_count/evaluation_count)*100 : 0`.

## Issues Encountered

- **`tsc -b` runs before `vite build` in `npm run build`.** routeTree.gen.ts is generated by the vite plugin, so on the first build it does not yet exist when tsc runs. Resolved by running `npx vite build` once first (generates routeTree.gen.ts, which has `@ts-nocheck`), then `npm run build`. After the first generation, routeTree.gen.ts is committed and tsc references the registered route types for `<Link to=...>` validation. Re-generation after adding the /login route required deleting the stale routeTree.gen.ts and re-running vite build.
- **node_modules/ and dist/ are tracked in this repo (no .gitignore for them).** Dep install + build produced many tracked changes; these were committed alongside the source changes per the existing repo convention (prior plans committed Cargo.lock/build artifacts similarly).
