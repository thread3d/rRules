## Objective

Establish DMN benchmark harness and memory profiling gates to measure parser throughput, FEEL evaluator latency, decision-table evaluation time, and memory consumption baselines — before optimization work in Phases 37–39. This phase does NOT optimize; it measures. The baselines become the regression floor for Phase 37+ gates.

## Scope

- **In scope:** Benchmark infrastructure (Criterion), memory profiling utility, baseline snapshots against v6.0 corpus, CI integration
- **Out of scope:** Actual optimization work (Phase 37–39) — this phase only measures

## Requirements

| ID | Description | Gate |
|----|-------------|------|
| PERF-01 | Benchmark harness measures parser throughput, FEEL evaluator latency, decision-table eval time, and DRD chain resolution time | PASS |
| PERF-02 | Memory profiling utility captures RSS peak, allocation counts, and per-phase breakdowns for the DMN subsystem | PASS |
| PERF-03 | Baseline snapshots from v6.0 corpus are saved as regression floor (JSON format) | PASS |
| PERF-04 | Benchmarks run in CI on PR (comment-only) and nightly (regression gate) | PASS |

## Success Criteria

1. `cargo bench --bench dmn_benchmarks` runs all four benchmark groups (parser, evaluator, decision-table, DRD) and produces Criterion output
2. Memory baseline snapshots exist for the v6.0 import corpus with RSS, allocation counts, and per-phase breakdowns
3. Benchmarks are integrated into CI — PR runs produce comments, nightly enforces regression gates
4. Documentation in `engine/benches/README.md` explains how to run benchmarks locally and interpret results

## Key Decisions

- **Criterion 0.5** for benchmarking (industry standard for Rust)
- **RSS via /proc/self/status on Linux**, Criterion allocation tracking as fallback for portability
- **Baseline format:** JSON with per-phase breakdowns, not binary — human-readable and diffable
- **CI threshold:** Nightly gate at 10% regression; PR runs are informational only (no merge gate)

## Dependencies

- Phase 29 (import corpus), Phase 31 (FEEL evaluator), Phase 32 (decision-table engine), Phase 33 (DRD resolution) — all must be in place before benchmarks can measure real workloads
