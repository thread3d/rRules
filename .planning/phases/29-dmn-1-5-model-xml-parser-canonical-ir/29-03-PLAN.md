<objective>
Implement the DMN XML exporter (`engine/src/dmn/exporter.rs`) that serializes the canonical IR back to `.dmn` XML using a `quick_xml::writer::Writer`, preserving annotations, descriptions, IDs, CDATA, and element order. This plan delivers DMN-06 and closes the round-trip loop started in Plans 29-01/29-02. The acceptance gate is a DOM-compare round-trip test against the import corpus: `parse(export(parse(input)))` must equal `parse(input)` for every fixture. The full byte-exact round-trip and DMNDI enrichment are Phase 35 (DMN-07); here the exporter ships structurally and the round-trip gate is exercised against the import corpus.

Purpose: Round-trip fidelity is structural from day one (Pitfall 11). The exporter proves the canonical IR carries enough information to regenerate the DMN document — nothing downstream needs to reconstruct DMN from a non-IR shape.
Output: `engine/src/dmn/exporter.rs`, `engine/tests/dmn_round_trip.rs`.
</objective>

Emit well-formed XML with an `<?xml version="1.0" encoding="UTF-8"?>` declaration and the DMN MODEL namespace on the root `<definitions>` element.

    Public API:
    - `pub fn export_dmn(model: &DmnModel) -> Result<String, DmnExportError>` — the main entry point. Returns the full `.dmn` XML document as a `String`.
    - `pub fn export_dmn_to_bytes(model: &DmnModel) -> Result<Vec<u8>, DmnExportError>` — bytes variant for file writing.

    Emission rules (match the parser's recognition exactly so round-trip works):
    - Root `<definitions>`: emit attributes `id` (if `Some`), `name` (if `Some`), `namespace` as `xmlns="..."` (the target namespace; if empty, use the DMN MODEL namespace `https://www.omg.org/spec/DMN/20200524/MODEL/` as default), `typeLanguage`, `expressionLanguage`, `exporter`, `exporterVersion` (each if `Some`). Emit the `<description>` child if `Some(text)` (emit as CDATA when `text.is_cdata`, else escaped text).
    - Iterate `definitions.children` in Vec order (preserve element order — Pitfall 11). For each `DefinitionsChild` variant, emit the corresponding element: `ItemDefinition` → `<itemDefinition>`, `Decision` → `<decision>`, `InputData` → `<inputData>`, `BusinessKnowledgeModel` → `<businessKnowledgeModel>`, `DecisionService` → `<decisionService>`, `KnowledgeSource` → `<knowledgeSource>`, `TextAnnotation` → `<textAnnotation>`, `Association` → `<association>`. Emit `id`/`name` attributes where `Some`.
    - `<itemDefinition>`: emit `id`, `name`, `isCollection` (only when `true`, to match DMN schema default), `typeLanguage`. Children: `<description>` (CDATA/escaped), `<typeRef>` (if `Some`), `<allowedValues>` (emit `<text>` for `UnaryTests(s)` — escaped/CDATA per a synthesized `TextContent`; emit `<item>` entries for `Enumeration(items)`), nested `<itemComponent>` recursively (each as an `<itemDefinition>`-shaped child — DMN schema nests `itemComponent`). Preserve `item_components` order.
    - `<decision>`: emit `id` (required — return `DmnExportError::InvalidModel` if the decision's id is `None`), `name`. Children in this order: `<description>`, `<question>`, `<allowedAnswers>`, `<variable>` (emit `<variable name=... typeRef=.../>` from `InformationItem`), `<informationRequirement>` for each `required_decisions` id (emit `<requiredDecision href="#id"/>`), `<knowledgeRequirement>`, then `<decisionTable>` if `Some`.
    - `<decisionTable>`: emit `id`, `name`, `hitPolicy` (always emit — use `HitPolicy::as_str`; the default `Unique` is emitted as `hitPolicy="UNIQUE"` so it round-trips explicitly; this is correct: the parser defaults absent→Unique, and emitting UNIQUE on export still round-trips because `parse("UNIQUE") == Unique`), `aggregation` (emit only when `Some` — COLLECT tables). Children: `<input>` for each `input_clauses` (emit `<inputExpression><text>...</text></inputExpression>`, `<inputValues>` if `Some`), `<output>` for each `output_clauses` (emit `name`, `typeRef`, `<outputValues>`, `<defaultOutputEntry><text>...</text></defaultOutputEntry>` if `Some`), `<rule>` for each `rules` (emit `<inputEntry><text>...</text></inputEntry>` per input entry, `<outputEntry>` per output entry, `<annotationEntry>` per annotation entry; emit `<description>` if `Some`). Preserve clause and rule order.
    - CDATA emission (DMN-06 + success criterion): for any `TextContent` with `is_cdata == true`, emit the text wrapped as `<![CDATA[ ...content... ]]>`. For `is_cdata == false`, emit the text with XML-escaped special characters (`&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`, `"` → `&quot;`). This preserves the CDATA-vs-plain distinction on round-trip (parser re-sets `is_cdata`).
    - DMNDI passthrough: if `definitions.diagrams` is non-empty, emit a `<DMNDI:DMNDI>` block (using the DMNDI namespace prefix `xmlns:dmndi="http://www.omg.org/spec/DMN/20180521/DMNDI/"` and DC/DI namespaces) with `<dmndi:DMNDiagram>`, `<dmndi:DMNShape>`, `<dc:Bounds>`, `<di:waypoint>` elements from the IR `DmnDiagram`/`DmnShape`/`DmnEdge`/`DcBounds`/`DcPoint`/`DmnLabel` structs. Emit in structural order (diagrams, then shapes, then edges). This carries DMNDI through round-trip (DMN-07 prep; full enrichment is Phase 35).

    Use `quick_xml::events::{BytesStart, BytesEnd, BytesText, Event}` with the `Writer`. For CDATA, use `Event::CData(BytesCData::new(content))`. For escaped text, use `Event::Text(BytesText::new(content))` (quick-xml escapes on `Text`). Do NOT use `quick_xml::se` (serde XML serialization loses attribute order/CDATA fidelity — same rationale as the parser). Map `quick_xml::Error` → `DmnExportError::XmlWrite(e.to_string())`.

    Do NOT parse DMN here (Plan 29-02). Do NOT evaluate FEEL. Do NOT touch `engine::data_types::Value` or the rule-engine `Expression`.
