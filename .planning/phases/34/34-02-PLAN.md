    **File structure:**
    ```typescript
    // frontend/src/lib/dmnSerializer.ts
    
    import type { HitPolicy, Aggregator } from '@/features/rules/types'
    
    // ---- Types (imported from types.ts):
    // - HitPolicy: 'UNIQUE' | 'ANY' | ... | 'COLLECT'
    // - Aggregator: 'SUM' | 'MIN' | 'MAX' | 'COUNT'  
    // - DecisionTableColumn: { id, label, accessorKey? }
    // - DecisionTableRow: { id, conditions: Record<string, unknown>, actions: Record<string, unknown> }
    
    // ---- Editor shape (what the React component tree owns):
    export interface EditorShape {
      columns: Array<{
        id: string
        label: string
        accessorKey?: string  // used as input_expression for conditions
        type: 'condition' | 'action'
      }>
      rows: Array<{
        id: string
        conditions: Record<string, unknown>
        actions: Record<string, unknown>
      }>
      hitPolicy: HitPolicy
      aggregator?: Aggregator  // only meaningful when hitPolicy === 'COLLECT'
    }
    
    // ---- DMN IR shapes (mirror engine/src/dmn/model.rs):
    export interface DmnInputClause {
      id?: string | null
      label?: string | null
      input_expression: string
      input_values?: unknown  // AllowedValues — not used in MVP
      description?: unknown | null
    }
    
    export interface DmnOutputClause {
      id?: string | null
      label?: string | null
      name?: string | null
      type_ref?: string | null
      output_values?: AllowedValuesShape  // Enumeration or UnaryTests — see below
      default_output_entry?: string | null
      description?: unknown | null
    }

    /** DMN AllowedValues shape (simplified for JSON transport). */
    export interface AllowedValuesShape {
      kind: 'enumeration' | 'unary_tests'
      values: Array<{ content: string; is_cdata: boolean }>
    }
    
    export interface DmnRule {
      id?: string | null
      description?: unknown | null
      input_entries: Array<{ text: { content: string; is_cdata: boolean } }>
      output_entries: Array<{ text: { content: string; is_cdata: boolean } }>
      annotation_entries: Array<{ text: { content: string; is_cdata: boolean } }>
    }
    
    export interface DmnDecisionTable {
      id?: string | null
      name?: string | null
      hit_policy: HitPolicy  // canonical DMN spec string
      aggregation?: 'SUM' | 'MIN' | 'MAX' | 'COUNT'  // only for COLLECT
      preferred_orientation?: string | null
      output_label?: string | null
      input_clauses: DmnInputClause[]
      output_clauses: DmnOutputClause[]
      rules: DmnRule[]
    }
    
    // ---- Mapper functions (the contract):
    
    /** Convert editor shape → DMN IR for evaluation or save */
    export function editorShapeToDmnIr(
      columns: EditorShape['columns'],
      rows: EditorShape['rows'],
      hitPolicy: HitPolicy,
      aggregator?: Aggregator,
    ): DmnDecisionTable
    
    /** Convert parsed DMN IR → editor shape for rendering */
    export function dmnIrToEditorShape(table: DmnDecisionTable): EditorShape
    ```

    **editorShapeToDmnIr implementation rules:**
    1. `input_clauses`: For each column where type === 'condition', create InputClause with `input_expression = accessorKey ?? label`. Label goes to `label` field if present.
    2. `output_clauses`: For each column where type === 'action', create OutputClause with `name = accessorKey ?? label`. Label goes to `label` field if present. **If the EditorShape carries an `allowedValues` array on the output column (from AllowedValuesEditor in Plan 03), map it into `output_values` as a `{ kind: 'enumeration', values: allowedValues.map(item => ({ content: item.text, is_cdata: false })) }` object** — this is how PRIORITY/OUTPUT ORDER hit policies carry their enumeration definitions through the round-trip.
    3. `rules`: Each row maps to a DmnRule — input_entries populated from `row.conditions[clause.label ?? clause.input_expression]`, output_entries from `row.actions[clause.label ?? clause.name ?? '']`. Each entry wraps in `{ text: { content: String(value), is_cdata: false }, ... }` (is_cdata=false because JSON preserves string content exactly; CDATA only matters for XML round-trip in Phase 35).
    4. `hit_policy`: Pass through as the canonical DMN spec string.
    5. `aggregation`: Only set when hitPolicy === 'COLLECT'. Otherwise omit (undefined → backend treats as no aggregation = array output per DMN spec §8.2.12).

    **dmnIrToEditorShape implementation rules:**
    1. Reverse of editorShapeToDmnIr: map input_clauses to condition columns, output_clauses to action columns.
    2. Each rule maps back to a row with conditions/actions populated from the entry arrays in clause order.
    3. Preserve hitPolicy and aggregation fields through round-trip.
    4. **If `output_values` is present on an OutputClause, extract it into the EditorShape's output column: read `{ kind, values }` where kind === 'enumeration', then map each value back to `{ id: crypto.randomUUID(), text: v.content }` AllowedValueItem form** — this restores the enumeration items that AllowedValuesEditor needs to render PRIORITY/OUTPUT ORDER columns.

    **CRITICAL — Pitfall avoidance (from RESEARCH.md):**
    - Column `accessorKey` IS the input expression name. Use it directly as the input key when building evaluate requests — never prefix with `input_${idx}_`.
    - HitPolicy values are EXACTLY DMN spec strings (`UNIQUE`, `RULE ORDER`, etc.) — never lowercase, never kebab-case.
    - COLLECT without aggregator returns array of outputs; frontend must handle both scalar and list output shapes in Plan 03.
