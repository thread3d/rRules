## Integration Findings (non-blocking WARNINGs — both RESOLVED 2026-07-06)

### WARNING 1 — `rule_filter` is a dead input (FRONTEND-03) — ✅ RESOLVED
- Frontend `TestRunner.tsx:130` sends `rule_filter: { name_pattern: ruleId }` on every Run (comment claims a "test this rule" UX).
- Backend `execute_single` (`api/src/v1/execution.rs`) **previously never read** `req.rule_filter`; the engine loaded ALL rules from the shared ruleset.
- **Fix (commit `384b1f17d`):** `execute_single` now calls a `filter_ruleset` helper (`Cow<'a, RuleSet>` — `Borrowed` for zero-clone on the no-filter hot path, `Owned` when filtering) that filters the loaded ruleset to rules whose `id` OR `name` equals `filter.name_pattern` before `engine.load_ruleset`. `rules_not_fired` is derived from the filtered set for consistency. Stateful-path scoping is intentionally out of scope (sessions execute the whole ruleset by design); the stateless path — which the frontend TestRunner uses (no `session_id`) — is now honored.
- **Regression tests (api/tests/execute_integration.rs):** `rule_filter_excludes_non_matching_rule` (filter `"r2"`, facts `score==0` → r1 excluded, `rules_fired==0`, `rules_not_fired==["r2"]` — the key proof, since without the filter r1 would fire); `rule_filter_matches_by_name` (filter `"Increment score"` → r1 fires); `rule_filter_no_match_loads_empty_ruleset` (filter `"does-not-exist"` → empty set, `rules_fired==0`, `rules_not_fired` empty).
- Note: the legacy duplicate `ExecuteRequest` at `api/src/models/execution.rs:8` (with `rule_filter` at `:19`) is fully dead code (no usages) — recorded as a separate cleanup item below, not touched by this fix.

### WARNING 2 — `/metrics` HTML + JSON arms hardcode `active_sessions: 0` (MON-07) — ✅ RESOLVED
- `api/src/metrics.rs` HTML + JSON arms **previously hardcoded** `active_sessions: 0`, while the Prometheus text arm gathered the live `rrules_sessions_active` gauge and the WS broadcast used `session_manager.len()`.
- **Fix (commit `384b1f17d`):** `metrics_endpoint` now takes `Option<web::Data<Arc<SessionManager>>>` and both the HTML and JSON arms read `session_manager.as_ref().map_or(0, |sm| sm.len())`. `Option` (not a required extractor) so minimal test apps that don't install a SessionManager (e.g. the auth allowlist test, standalone metrics tests) degrade to 0 — backward-compatible, no existing test breaks. Production `main.rs:224` installs the SessionManager in `app_data` → `Some` → live count.
- **Regression test (api/tests/execute_integration.rs):** `metrics_json_active_sessions_live` (POST `/v1/execute` with `session_id: "metrics-live-session"` to create a session, then GET `/metrics` `Accept: application/json` → asserts `active_sessions>=1`).
