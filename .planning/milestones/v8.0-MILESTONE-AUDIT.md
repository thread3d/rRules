## Post-close-out re-verification (2026-10-25)

The audit above was written from phase summaries, not from executed evidence.
A re-verification pass executed the suites and found the following, all now
fixed (details and evidence in `TCK-COVERAGE-GAPS.md`):

| Finding | Severity | Status |
|---------|----------|--------|
| `engine/src/dmn/test_util.rs` structural comparator looped forever on the first attribute-less tag and emitted malformed normalised XML | High — 5 unit tests hung; the round-trip comparison gate compared garbage | FIXED (`canonicalize_tags`, CDATA unwrapping, no debug output) |
| Two `discover_tck_vectors` unit tests used a fixture layout the discovery code does not support | Medium — permanently RED | FIXED (tests now use the upstream `<vector>-test-NN.xml` convention) |
| Multi-word FEEL function names were truncated by the parser (`upper case("x")` → `Name("upper")`) | High — every multi-word built-in returned `null` inside real DMN models | FIXED (`Parser::merge_multiword_name` + `builtins::multi_word_builtin_names`) |
| `sort(list, comparator)` ignored the comparator | High — Phase 41's headline claim was not implemented | FIXED (`eval::apply_function_value`, boolean + numeric comparators) |
| `round up/down/half up/half down` ignored `scale` | High — `round half up(1.25, 1)` returned `1` | FIXED (scale-aware `RoundingStrategy`) |
| `get entries(c)` returned strings; `years and months duration` had no two-date form | High — two TCK vectors only "passed" via unrelated cases | FIXED |
| `retract_fact` was a stub in Rete/TREAT/LEAPS despite passing-summary claims; 4 retraction tests RED | High — listed as tech debt since v4.0 | FIXED (alpha/beta/work-memory removal, cache + aggregate invalidation) |
| TCK evaluator layer accepted a vector when *any one* case matched and compared only the first scalar | High — the 51/51 metric was not structure-aware | FIXED (`engine/tests/tck_values.rs` typed parser + strict all-cases comparison) |
