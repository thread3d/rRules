# Milestone v8.0 — Close TCK Evaluator Gaps (Phases 40–43)

**Shipped:** 2026-07-15
**Audit:** [`v8.0-MILESTONE-AUDIT.md`](v8.0-MILESTONE-AUDIT.md) — `passed`

**Milestone Goal:** Raise TCK evaluator coverage from 21/51 to 51/51 vectors by
implementing the missing FEEL built-in functions across numeric, string, list,
context, relational, and temporal families, then verify conformance and close
out the milestone.

**Scope locks (user decisions):**

- v8.0 is a focused built-in-function gap-closing milestone — no new DMN
  features, no frontend changes, no new API endpoints.
- All 30 vectors that already parse and round-trip cleanly must continue to do
  so (zero regression).
- Each new built-in function must handle null propagation per DMN 1.5
  Section 10.3.4.
- The existing Rete rule-execution path (`/v1/execute`, `EngineRegistry`) is
  unchanged — zero regression.
- Phase numbering continues from 40 (v7.0 ended at Phase 39).

## Phase 40: Numeric Built-in Functions

**Goal**: All 14 numeric TCK vectors pass the evaluator layer — users can use
abs, sqrt, exp, log, even/odd, modulo, number(), median/mode/stddev, and
product in FEEL expressions with correct DMN 1.5 semantics.
**Depends on**: Phase 31 (FEEL evaluator core + built-in function registry),
Phase 30 (FEEL value types + Decimal128 numeric domain)
**Requirements**: FEEL-01, FEEL-02, FEEL-03, FEEL-04, FEEL-05, FEEL-06, FEEL-07,
FEEL-08, FEEL-09, FEEL-10
**Success Criteria** (what must be TRUE):

  1. `abs(number)` returns the absolute value for Integer and Number inputs, and
     propagates null — TCK vector `0050-feel-abs-function` passes.
  2. `sqrt(number)` returns the square root for positive inputs and null for
     negative inputs — TCK vector `0051-feel-sqrt-function` passes.
  3. `exp(number)` and `log(number)` compute correctly; `log` returns null for
     non-positive inputs — TCK vectors `0052-feel-exp-function` and
     `0053-feel-log-function` pass.
  4. `even(number)` / `odd(number)`, `modulo(dividend, divisor)`,
     `number(from, grouping, decimal)`, `median(list)`, `mode(list)`,
     `stddev(list)`, and `product(list)` all return correct results per DMN 1.5
     Section 10.3.4.1 — TCK vectors `0054`–`0056`, `0058`, `0061`–`0063`, `0094`
     pass.
  5. Arithmetic edge cases (empty-list SUM/MIN/MAX returns null, negation edge
     cases) are handled correctly — TCK vectors `0100-arithmetic` and
     `0099-arithmetic-negation` pass.

**Plans**: 3 plans — all complete

- [x] 40-01-PLAN.md — abs() duration support + named parameter resolution
- [x] 40-02-PLAN.md — number(from, grouping, decimal) 3-arg form
- [x] 40-03-PLAN.md — Edge case unit tests + TCK verification

## Phase 41: String + List Built-in Functions

**Goal**: All string and list TCK vectors pass the evaluator layer — users can
use split, filter, concatenate, insert/remove, sort/list contains, all/any, and
singleton/list semantics in FEEL expressions with correct DMN 1.5 semantics.
**Depends on**: Phase 40 (numeric built-in functions establish the built-in
registry pattern)
**Requirements**: FEEL-11, FEEL-12, FEEL-13, FEEL-14, FEEL-15, FEEL-16, FEEL-17
**Success Criteria** (what must be TRUE):

  1. `split(string, delimiter)` returns a list of substrings per DMN 1.5
     Section 10.3.4.2 — TCK vector `0067-feel-split-function` passes.
  2. `filter(list, function)` returns a filtered list using a FEEL
     lambda/function as the second argument — TCK vector `0001-filter` passes.
  3. `concatenate(list1, list2, ...)` returns a concatenated list — TCK vector
     `0010-concatenate` passes.
  4. `insert(list, position, element)` and `remove(list, position)` return new
     lists with correct element manipulation — TCK vector `0011-insert-remove`
     passes.
  5. `sort(list)` / `sort(list, function)` and `list contains(list, element)`
     return correct ordering and membership results — TCK vectors `0013-sort`
     and `0069-feel-list` pass.
  6. `all(list)` and `any(list)` return correct quantifier results — TCK
     vectors `0059-feel-all-function` and `0060-feel-any-function` pass.
  7. Singleton lists and single elements behave correctly per DMN 1.5
     singleton/list semantics — TCK vector `0021-singleton-list` passes.

**Plans**: 1 plan — complete

- [x] 41-01-PLAN.md — sort() comparator lambda support, empty-list guard,
      split/filter edge-case tests

## Phase 42: Context + Relational + Temporal Built-in Functions

**Goal**: All context, relational, and temporal TCK vectors pass the evaluator
layer — users can use context construction/navigation, get value, get entries,
deep equality, between, and temporal built-in functions in FEEL expressions
with correct DMN 1.5 semantics.
**Depends on**: Phase 41 (string/list built-in functions establish the pattern
for context/temporal families)
**Requirements**: FEEL-18, FEEL-19, FEEL-20, FEEL-21, FEEL-22, FEEL-23, FEEL-24
**Success Criteria** (what must be TRUE):

  1. Context literal evaluation with proper scoping works correctly — TCK
     vector `0057-feel-context` passes.
  2. `get value(context, key)` returns the value for a given key in a context —
     TCK vector `0080-feel-getvalue-function` passes.
  3. `get entries(context)` returns a list of key-value entries from a context —
     TCK vector `0081-feel-getentries-function` passes.
  4. Deep equality (`=` / `!=`) works correctly across all FEEL types including
     context, list, and temporal types — TCK vector `0068-feel-equality` passes.
  5. `between(value, start, end)` returns true when value is in the range
     [start, end] — TCK vector `0071-feel-between` passes.
  6. Temporal built-in functions (`date()`, `time()`, `date and time()`,
     `duration()`) handle string-to-temporal parsing and temporal arithmetic
     correctly — temporal family TCK vectors pass.
  7. All remaining Section 10.3.4 built-in functions not covered in Phases 40-41
     are implemented — all 51 TCK vectors have evaluator-layer passes.

**Plans**: none required — verified pre-existing implementation (Phase 31).

**Plans**: none — close-out phase (verification + audit + tag).
