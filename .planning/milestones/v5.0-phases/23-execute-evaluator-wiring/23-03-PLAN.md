<objective>
Build the real direct rule evaluator on ReteEngine — the keystone of Phase 23. This is where rules actually start firing.

Purpose: `ReteEngine::execute_rules` (rete/mod.rs:321) is a placeholder that iterates action_nodes × join_nodes × nagrams and increments a counter without ever evaluating a condition or applying an action. ROADMAP success criterion #1 (`score := score + 10` → `rules_fired >= 1` + incremented `facts_after`) cannot pass until this is rewritten into a real evaluator. This plan implements the direct interpreter (D-04), the fixpoint-with-cap forward-chaining loop (D-07), and the once-per-rule coverage recording (L-06 / Pitfall 6). It depends on Plan 01 (trait bridge + import fix) and Plan 02 (Expression + Condition extensions).

Output: A ReteEngine that actually evaluates conditions, applies computed-expression actions to working memory, chains to fixpoint under a configurable cap, records coverage once per fired rule, and exposes post-execution facts via get_facts.
</objective>

    3. Fixpoint loop: `for _pass in 0..max_iter { let mut newly_fired_this_pass = false; for rule in &self.rules { if fired_set.contains(&rule.id) { continue; } let facts: Vec<&Fact> = self.working_facts.values().collect(); evaluated_set.insert(rule.id.clone()); if rule.condition.evaluate(&facts) { // apply actions let fired_rule_id = rule.id.clone(); for action in &rule.actions { apply_action(action, &mut self.working_facts); } fired_set.insert(fired_rule_id); newly_fired_this_pass = true; } } if !newly_fired_this_pass { break; } }`

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-06 | Denial of Service | ReteEngine::execute_rules forward-chaining | HIGH | mitigate | D-07 fixpoint cap: the loop runs at most `max_iter` passes (default 1000, configurable via RRULES_MAX_CHAIN_ITERATIONS); a cyclic rule set terminates at the cap without panicking (Task 2 behavior + acceptance criterion). High severity because an unbounded loop hangs the server; the cap is mandatory. |
| T-23-07 | Tampering | CoverageTracking recording | medium | mitigate | L-06 / Pitfall 6: fired ids collected in a HashSet and record_rule_fire called exactly once per fired rule after the loop (not inside the inner loop), so coverage data is not double-counted and dead-rule detection (Phase 26) reads truthful fire counts |
| T-23-08 | Denial of Service | apply_action Expression evaluation | medium | mitigate | Expression::evaluate (Plan 02) returns Value::Null on division by zero rather than panicking; the fixpoint cap bounds total work; CallFunction is a no-op in Phase 23 so user-authored function calls cannot dispatch arbitrary code |
| T-23-09 | Denial of Service | per-request engine construction | low | accept | ReteEngine::new() is O(1) and load_ruleset is O(rules); per-request construction (L-03) avoids shared mutable state — no pool needed (23-RESEARCH.md Flag 4) |
